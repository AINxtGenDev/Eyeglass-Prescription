# Phase 3 — UI Design Contract

> Visual and interaction contract for frontend phases. Generated by gsd-ui-researcher, verified by gsd-ui-checker.

**Mode:** `--auto`. No questions were asked. The user's instruction (03-CONTEXT.md) was "use best practice and focus is photorealistic 3D and as correct as possible result". Every value below comes from an upstream artifact (source noted) or is marked **[BP]** = Claude's best-practice decision with its reason. The priority order for every [BP] choice is: correctness first, then photorealism, both kept within lay usability ("as easy as possible") and mid-range-phone performance (VIZ-06).

**Baseline (read 2026-11-08):** `src/ui/style.css` (tokens `--fg`, `--muted`, `--bg`, `--surface`, `--line`, `--accent`, `--accent-tint`, `--error`, `--hint`, `--bar-bg`, `--bar-focus`, `--space-1…16`), `index.html` (`#view-slot` is the first child of `.col-results`; `#bar-view-slot` is the first child of `#summary-bar`; both are empty and `hidden`), `src/ui/summary-bar.js`, `src/i18n/de-AT.js` (no `view.*` keys yet), `vite.config.js` CSP. **This spec extends 02-UI-SPEC.md and replaces none of it.** Phase 2 rules that still apply here: the tokens, the 4 type sizes, the 2 weights, 44 px targets, the 3 px focus ring, the rule "text or icon, never colour alone", de-AT through `t()`, the ban on "Stärke", and 320 px with no horizontal scroll.

## Revision 1 amendments (lens-critic plan review, 2026-11-08)

These override the rows they name; each affected row below carries an "(amended, R1-n)" marker. The plans cite them.

- **R1-1 Placement on phones (MAJOR 5; D-14 revised):** below 900 px `#view-slot` sits in the DOM directly after `section#result` (moved by `src/ui/view-place.js`, 03-06), so the first card value is on screen before the 3D view. On ≥ 900 px it stays the first child of `.col-results` (D-13). DOM move, not CSS `order`. UX-03 is met by the bar thumbnail.
- **R1-2 Keyboard order:** follows R1-1. On desktop the view comes before the result cards; on phones it comes after section#result.
- **R1-3 Seite (MAJOR 2):** target = the temporal outer rim point of the side eye; distance = box fit of that eye's lens + rim side silhouette (y and z half-extents + 8 %), not "frame front + temples". Side eye = the larger total edge protrusion (front + back of bevelSplit at etMax), ties within 0,05 mm → right eye (MINOR 13).
- **R1-4 OrbitControls limits (MAJOR 2):** derived from the presets on every frame attach: minDistance = 0,5 × the smallest preset distance, maxDistance = 2 × the largest, maxTargetRadius = the largest preset-target distance + 20 mm.
- **R1-5 Dickenkarte camera (MAJOR 4):** Vorne direction, framed on the heat eye's lens + rim (box fit); the eye picker re-frames. Callouts are all-or-nothing: if any callout finds no free spot (five candidate offsets), none is shown and `view.callout.tableOnly` says that all values are in the table.
- **R1-6 Touch path (MINOR 8):** chosen with `any-pointer: coarse` (not `pointer: coarse`), so hybrid touch laptops never trap touch scrolling. The quality tier keeps `pointer: coarse` (device class).
- **R1-7 Protrusion copy (MAJOR 1, MINOR 10):** edge lines name the edge: `view.protrusion.both|front|back` = '{Rechts/Links}: Glasrand vorne {front}, hinten {back} aus der Fassung' / '… Glasrand vorne {front} aus der Fassung, hinten bündig' / '… Glasrand hinten {back} aus der Fassung, vorne bündig'; `view.protrusion.none` = '{Rechts/Links}: Glasrand passt ganz in die Fassung'; new `view.protrusion.lead` = '{Rechts/Links}: Vorderfläche bis zu {lead} vor der Fassung' and `view.protrusion.leadNone` = '{Rechts/Links}: Vorderfläche nicht vor der Fassung'; `view.protrusion.assumed` = 'Berechnet mit Randtiefe {rim} (angenommener Wert, keine Herstellerangabe; in der Experten-Ansicht änderbar).' The Expert rim block gets the matching `frame.rim.lead` / `frame.rim.leadNone` lines (03-01).
- **R1-8 Thumbnail (MINOR 5, MINOR 11):** rendered with a front pose fitted to the frame-front box (lenses, rims, bridge; no temples), in the current screen layout; in split A/B the shown half is cropped with drawImage's source rectangle (no single full-frame render). The camera pose is restored and the main view re-rendered in the same task.
- **R1-9 Timing labels (MINOR 4):** input → 3D paint ≤ 200 ms is the INP "good" threshold (web.dev/articles/inp), not RAIL; the RAIL response budget is ENG-09 (c)'s 100 ms, which is re-measured with the 3D view active (MAJOR 3). Proxy 3D numbers are labelled "worker unthrottled".
- **R1-10 Lens depth (MINOR 9):** both lenses are referenced to one rim plane (each eye's mean bevel apex at z = 0); the frame's rims and bridge stay in that plane.

**Hard constraints carried in:**
- The CSP stays unchanged: `img-src 'self' data:`, `style-src 'self'`, `script-src 'self'` (the `worker.spec.js` test checks the CSP string exactly).
- Styling goes through classes or `el.style.prop = …` only. No inline `style` attribute and no `<style>`.
- Textures are drawn by our own canvas code. Nothing comes from `references/`.
- One `WebGLRenderer`, one GPU context (D-14, D-24).
- Three.js is lazy-loaded after the first result paint (D-16).

### Scene colours (new; sRGB values as authored, before tone mapping) **[BP]**

| Element | Value | Reason / check |
|---------|-------|----------------|
| Scene background (renderer clear colour, not tone-mapped) | `#f3f4f6` | Matches `--surface`. Check: a pixel sampled in a screenshot corner equals `#f3f4f6` ± 2 per channel. |
| Eye-chart / checkerboard plane | `#1a1a1a` squares and letters on `#ffffff` | Highest contrast (17,4:1). Uses the page tokens `--fg` and `--bg`. |
| Frame (acetate) | base colour `#221e1c` | Warm near-black acetate: 14,9:1 against the background, so the frame silhouette is always clear. It must stay **opaque** (no `transmission`): a transmissive frame would disappear behind the lenses (PITFALLS 13). |
| Lens edge band | base colour `#6f8a84` (polished glass edge, grey-green) | 3,38:1 against the background and 4,43:1 against the frame: the protruding edge in Seite stays visible as a graphic (WCAG 1.4.11 ≥ 3:1). The band is **opaque** for the same reason as the frame: it stays visible behind the other lens in Seite/Oben. |
| Lens faces | transmissive, colourless (no AR tint) | D-08 allows a cosmetic tint. **[BP] none**, because a tint implies a coating the user did not choose. |
| Contact shadow | `#1a1a1a`, radial falloff, peak opacity 0,25 | Grounding only (D-11). |

### Heatmap colours (VIZ-05, D-22) **[BP]**

- **Palette: cividis** (Nuñez, Anderton & Renslow 2018, PLOS ONE 13(7): e0199239). It was designed for colour-vision deficiency, and its luminance rises monotonically, so the map stays readable in greyscale. It is chosen over viridis for CVD safety. 11-stop LUT, verified from matplotlib 3.11.2 `colormaps['cividis']` on 2026-11-08:
  `#00224e #083370 #35456c #4f576c #666970 #7d7c78 #948e77 #aea371 #c8b866 #e5cf52 #fee838` (t = 0,0 … 1,0). The LUT is interpolated linearly in sRGB between the stops.
- **Direction:** **thicker = darker.** Colour = cividis(1 − t), with t = (thickness − scaleMin) / (scaleMax − scaleMin). The thinnest point is light yellow `#fee838`, the thickest dark navy `#00224e`. The legend says this in words ("dunkler = dicker"), so the direction never rests on colour.
- **Unlit:** heatmap faces render with an unlit material and `toneMapped: false`, so each pixel colour equals the legend colour. A lit, shaded map would not match its own legend.
- **Iso-lines:** 2 px. The colour is chosen per fragment from the LUT position: `#ffffff` where the LUT t < 0,5, and `#1a1a1a` where t ≥ 0,5. The lowest contrast of any line against its underlying map colour is 4,17:1 (computed 2026-11-08 with the WCAG relative-luminance formula over all 11 stops).

## 3D Scene Contract (VIZ-01, VIZ-02, VIZ-04; D-01…D-12)

### Correctness (governs everything)

- **1 scene unit = 1 mm** (D-01). Lenses, frame, temples, the chart distance and the camera distances are in mm.
- The lens meshes come only from the pure-JS geometry builder over the engine surfaces and outline (D-02, D-03). The view never edits positions. Visual tests do not replace the D-04 Node tests.
- **Axes [BP]:** origin = bridge centre in the frame front plane; +y up; +z toward an observer facing the wearer; the wearer's right lens (R/OD) is at −x, so it appears on the **viewer's left** in Vorne, as an optician sees it. The eye labels "R" and "L" (below each lens, projected HTML) resolve this for lay users.
- Every number shown in or beside the view (callouts, iso values, protrusion, aria summary) is an **engine value** formatted by `format.js`. Nothing is read back from the mesh or from pixels (D-04e).

### Renderer and look (D-07, D-12) **[BP] values**

| Setting | Value | Reason |
|---------|-------|--------|
| Renderer | `WebGLRenderer({ antialias: true, alpha: false, powerPreference: 'high-performance' })` | MSAA is fixed when the context is created. Tile GPUs on phones resolve 4× MSAA cheaply, so it is on in all tiers. |
| Output | `outputColorSpace = SRGBColorSpace` | Physically based output |
| Tone mapping | **`NeutralToneMapping`** (Khronos PBR Neutral), `toneMappingExposure = 1.0` | Neutral is built for product rendering: it keeps base colours and whites faithful. AgX greys whites and desaturates, which would dull the black-on-white chart and change the frame colour. Source: three.js `tonemapping_pars_fragment.glsl.js` (Context7, 2026-11-08), which links modelviewer.dev/examples/tone-mapping. |
| Environment (IBL) | `RoomEnvironment` → `PMREMGenerator.fromScene(…, 0.04)` → `scene.environment`; then dispose the generator | Procedural studio reflections on glass and clearcoat; no HDRI download, no licence (D-07) |
| Visible background | `scene.background = new Color('#f3f4f6')` (not the environment) | Seamless studio look; matches the page |
| Direct lights | none | The IBL alone gives soft studio light, with no shadow maps (D-11) |
| Rendering | on demand only (D-20): after a re-mesh, while controls change or damp, during a preset tween, on resize, on a tier change | Battery and heat on phones |

### Materials (D-08, D-09)

| Part | Material | Parameters |
|------|----------|-----------|
| Lens front and back faces | `MeshPhysicalMaterial` | `transmission: 1`, `ior: n_e` of the selected material (custom included), `thickness`: the engine CT in mm (scalar; PITFALLS 13), `roughness: 0`, `metalness: 0`, `opacity: 1`, `side: FrontSide` on each face mesh with correct winding (avoids three.js #28131 DoubleSide issue), `specularIntensity: 1`. Dispersion: High tier only, and only if the planner cites a mapping from the Abbe number to the three.js `dispersion` parameter. Otherwise `0`, noted in Technische Angaben. |
| Lens edge band | `MeshPhysicalMaterial`, opaque | `color #6f8a84`, `roughness: 0.35` (polished-frosted edge look), `clearcoat: 0.5`, `clearcoatRoughness: 0.2`, no transmission |
| Frame rim, bridge, end pieces, temples | `MeshPhysicalMaterial`, opaque | `color #221e1c`, `roughness: 0.4`, `clearcoat: 1`, `clearcoatRoughness: 0.08` (polished acetate) |
| Hinge block | `MeshStandardMaterial` | `color #9a9a9a`, `metalness: 1`, `roughness: 0.3` |
| Chart plane | `MeshBasicMaterial`, `toneMapped: false` | Own canvas texture; colours exactly `#1a1a1a` / `#ffffff` |
| Contact shadow | `MeshBasicMaterial`, `transparent`, `depthWrite: false` | Own radial-gradient canvas texture (256×128), drawn once. When the frame size changes the plane is scaled, never redrawn. |
| Heatmap faces | unlit, `vertexColors`, `toneMapped: false` + iso-line shader (fwidth technique or line geometry; planner's choice, CONTEXT discretion) | Replaces only the lens-face material while Dickenkarte is on. The edge band, frame and chart stay. |

The Glas and Dickenkarte materials are both created once and swapped. They are disposed only on teardown (D-26).

### Frame geometry presentation (D-06, D-09)

- Rim: follows the same outline as the lens, has the rim depth from the Expert field (default `RIM_DEPTH_DEFAULT_MM`), and a visible face width of 4 mm front-on **[BP, labelled design value "angenommener Wert" in Technische Angaben]**. The bridge spans exactly DBL. The end pieces sit at the temporal top of each rim.
- Temples: the length is the stamp's third number, otherwise 140 mm (D-06), with a 30° earpiece bend over the last 35 mm **[BP, design value]**. Temples open at 95° to the frame front (5° outward splay), as in product photos.
- **Seite near-temple fade [BP]:** when the camera azimuth is within 30° of a pure side view, the temple and hinge on the camera side render at 25 % opacity. Otherwise the hinge block hides the upper lens edge, which is what the side view exists to show. The far temple stays opaque.

### Background chart (D-10) **[BP]**

- One vertical plane, 600×400 mm, centred at (0, 0, −200) mm. It sits 200 mm behind the frame front, so it lies beyond the 140 mm temples plus the bend and no temple pierces it. The distance is documented as a design value.
- Texture drawn at runtime: a 10 mm checkerboard over the whole plane, crossed at y = 0 by a white band 24 mm high carrying the letter row `E F P T O Z L P E D` repeated, 12 mm cap height, `#1a1a1a`, weight 600 system sans-serif. Behind each lens you see straight checker edges (they show the bending) and letters (they show scale).
- Texture size: 2048×1366 on the High tier, 1024×683 on Mittel and Sparsam. Mipmaps on, anisotropy `min(8, getMaxAnisotropy())`.
- **Grazing fade:** the chart plane is hidden when the camera is more than 70° from the plane normal (Seite and Oben). Otherwise it shows as a distracting black-and-white sliver. In those views the glasses stand on the plain studio background.

### Contact shadow (D-11)

A horizontal plane at y = −(B/2 + 25 mm), with the footprint of the frame front plus temples and a soft ellipse. It is static: no real-time shadow maps on any tier.

### Quality tiers (D-12) **[BP thresholds]**

| Tier (Technische Angaben wording) | When | Pixel ratio | `transmissionResolutionScale` | Dispersion | Chart texture |
|------|------|-------------|------|------|------|
| **hoch** | start: not (`pointer: coarse` AND `min(screen.width, screen.height) < 768`) | `min(devicePixelRatio, 2)` | 1 | on (if sourced) | 2048 |
| **mittel** | start: `pointer: coarse` AND `min(screen.width, screen.height) < 768` (phones) | `min(devicePixelRatio, 1.5)` | 0.5 | off | 1024 |
| **sparsam** | runtime: median orbit frame time > 20 ms over the last 30 interaction frames on the current tier (hoch → mittel → sparsam, one step down at a time, never back up within the session) | 1 | 0.35 | off | 1024 |

**Geometry resolution is identical in every tier.** The tessellation that meets the D-04(c) 0,01 mm bound is never reduced. Realism degrades by tier; correctness never does. A tier change disposes and recreates only render targets and textures, and it is logged in Technische Angaben.

## Camera and Controls (VIZ-03, D-15, D-18…D-20)

### Camera **[BP]**

- One `PerspectiveCamera` with a **vertical FOV of 20°** in every view. This long focal length, like product photography, keeps perspective distortion small, so the Seite view is close to orthographic and protrusion reads true to scale (D-19 allows a long-focal perspective). It also avoids switching camera types.
- The distance is fitted to the bounding sphere of the visible object plus an 8 % margin, recomputed when the frame changes (an animated fit only if the user has not orbited away since the last preset).

| Preset | Target | Direction (azimuth / elevation) | Fits |
|--------|--------|---------------------------------|------|
| Default and "Ansicht zurücksetzen" | bridge centre | 35° toward the wearer's right side, 15° above | frame front + temples |
| Vorne | bridge centre | 0° / 0° | frame front only |
| Seite | temporal rim point of the **side eye** | 90° from the side eye's temporal side / 0° | side eye's lens + rim silhouette (amended, R1-3) |
| Oben | bridge centre | 0° / 85° from above | frame front + temples |

- **Side eye [BP]:** the eye whose thickest edge has the larger total protrusion, front + back (D-05 rule; amended, R1-3). Ties within 0,05 mm go to the right eye. In A/B mode it is the compared eye. `#view-side-note` then names it, because the view would otherwise look the same for either eye.
- **Transition:** 450 ms ease-in-out (cubic) on position and target. Under `prefers-reduced-motion: reduce` it is an instant cut and damping is off. There is no auto-rotate anywhere.

### OrbitControls limits

`enableDamping: true` (`dampingFactor: 0.08`), `minDistance`, `maxDistance` and `maxTargetRadius` derived from the presets (amended, R1-4; the former 0,35 × / 2 × default and 60 mm clamped the Seite target and blocked a close-up), `minPolarAngle: 0.05`, `maxPolarAngle: π − 0.05`. The glasses cannot be lost from view (D-20).

### Pointer and touch (D-15) **[BP]**

| Device | At rest | Active |
|--------|---------|--------|
| Fine pointer (mouse/trackpad) | Drag rotates; Shift + drag or right-drag pans. **The wheel zooms only while `#view-stage` has focus** (clicking it focuses it). Wheel events without focus scroll the page. | same |
| Touch (`any-pointer: coarse`, amended R1-6) | The view is static: `touch-action: pan-y pinch-zoom` on the stage, controls disabled, page scrolling passes through. Preset buttons work. | After "3D drehen" (`aria-pressed="true"`): `touch-action: none` on the stage only; one finger rotates, two fingers pinch-zoom and pan. |

- **Leaving the active state:** another tap on "3D drehen", or automatically when less than 50 % of the stage is in the viewport (IntersectionObserver), so the canvas can never trap scrolling. Choosing to make it explicit beats a first-tap activation: a first tap on a scrolling page is often a scroll start.
- Hover alone never zooms. The page never scrolls because of the 3D view.

### Keyboard (D-20) **[BP: own handler instead of `listenToKeyEvents`]**

`OrbitControls.listenToKeyEvents` maps the plain arrow keys to **pan** (default `keys` = Arrow*, per the three.js docs), which surprises lay users, and it offers no zoom keys. So `#view-stage` gets its own `keydown` handler that drives the same camera state:

| Key (stage focused) | Action |
|---------------------|--------|
| ← / → | rotate the azimuth 15° |
| ↑ / ↓ | rotate the elevation 10° (within the polar limits) |
| Shift + arrows | pan 5 mm |
| `+` / `=` and `-` | zoom in or out by a factor of 1,25 |
| Home ("Pos1") | Ansicht zurücksetzen |

Handled keys call `preventDefault()`, so the column does not scroll; all other keys pass through. Tab leaves the stage normally (no trap). The preset buttons follow the stage in tab order.

## Heatmap (VIZ-05, UX-02, D-21…D-23, D-25)

- **Switch:** `fieldset#view-mode.segmented`, Expert only (`data-expert hidden`, with the `.expert-tag`). Options Glas | Dickenkarte; Glas is the default and is not persisted. Turning Expert off while Dickenkarte is on returns to Glas.
- **Entering Dickenkarte** animates the camera to Vorne, framed on the heat eye (D-21; amended, R1-5). Orbit stays possible.
- **Shared scale (D-23, D-25):** scaleMin = the minimum over all displayed lenses of the thinnest point; scaleMax = the maximum of the thickest point (thickest(m)). Both are engine metrics. Both eyes count, and in A/B mode all four lenses count. The range is rounded outward to the iso step.
- **Iso step [BP]:** the smallest step from {0,1; 0,2; 0,25; 0,5; 1; 2} mm that gives ≤ 8 lines inside the range. If even that gives fewer than 2 lines, the narrow-range sentence (Copywriting) replaces the step line, and the callouts still carry the numbers.
- **Callouts (D-22):** HTML labels projected from 3D, on the **one eye selected** in `#view-heat-eye` (default: the eye with the larger thickest point). In a 400 px or smaller view, ten labels around two ~110–150 px lenses would overlap; both lenses are still coloured. Five fixed callouts: Mitte (the optical centre), innen, außen, oben, unten. The four edge callouts sit where the horizontal and vertical lines through the optical centre meet the outline. Their values come from the engine's `thicknessAt` at those exact points (D-04e). A sixth callout, "dickste", is added at the location of the engine's thickest edge when that point is more than 10° of polar angle from all four edge callouts. Otherwise the nearest callout gets the suffix " · dickste".
- **Callout visual:** an 8 px marker dot at the point. The label pill (`--bg`, 1 px `--line` border, 4 px radius, 4×8 px padding, 14 px 600 tabular) is offset 8 px outward from the optical centre, so it covers the map as little as possible. The Mitte label goes below-right of its dot.
- **Iso-line labels:** each line is labelled once with its value without a unit ("2,5"; the legend says mm). The label sits where the line crosses the horizontal through the optical centre on the temporal side, or failing that at the line's topmost point. It uses the same pill style, weight 400. **Collision priority:** callouts > eye labels > iso labels. An iso label that would overlap anything is dropped (its value stays on the legend ticks).
- **Legend `#view-legend`:** inline SVG, full width, max 400 px. Title "Dicke in mm" (14 px 600). A 16 px gradient bar built from SVG `<linearGradient>` with the 11 LUT stops as `stop-color` presentation attributes (CSP-safe). Ticks at every iso value plus both range ends, with 14 px labels below. The end words "dünner" (left) and "dicker" (right) are text. `role="img"` + `<title>` "Farbskala der Dicke" + `<desc>` "Von {min} (dünner, hell) bis {max} (dicker, dunkel), Linien alle {step}."
- **Text equivalent `#view-heat-table`** (always shown in Dickenkarte; this is the colour-free source): caption "Dicke an markanten Stellen". Columns: Stelle · Rechtes Glas · Linkes Glas. In A/B mode the columns are Stelle · Vorher (A) · Nachher (B) for the compared eye, and the caption names the eye. Rows: Mitte (optischer Mittelpunkt) · innen (nasal) · außen (temporal) · oben (superior) · unten (inferior) · dickste Stelle (with its location word). It uses the phase-2 table styles and stacked mode below a 480 px container.

## A/B in 3D (RES-03, D-24, D-25)

- **Layout [BP refinement of D-24]:** while the comparison is active, the view shows **the compared eye only**, as two scissor viewports **side by side** (A left, B right). One renderer and one shared camera relative to each lens's own boxing centre, so both halves show the same angle at the **same mm-per-pixel scale**. A smaller frame in B therefore really looks smaller. This works whenever the stage is ≥ 360 px wide (each half ≥ 180 px holds one ~55 mm lens): the 400 px desktop column and phones of 400 px or more. Below 360 px (320 px phones) a single viewport follows the existing `#cmp-show` Vorher | Nachher toggle, with the camera kept (D-24 phone path).
  - Reason: the desktop results column is only 400 px wide. Two whole pairs of glasses at 200 px each would show lenses about 70 px wide, too small to judge thickness. One lens per half is the meaningful comparison and keeps D-24's synchronised camera.
- **Compared eye:** the eye with the larger thickest point across A and B. Ties go to the right eye.
- Captions as projected HTML at the top-centre of each half: "Vorher (A)" / "Nachher (B)" (14 px 600 on a `--bg` pill). A 2 px `--line` divider sits between the halves. Below the stage, `#view-caption` reads the A/B caption line. Orbit and presets act on both halves.
- In Dickenkarte, A and B share one scale and legend (D-25), and the callout eye is the compared eye (the eye picker is hidden in A/B). The phase-2 difference sentence `#cmp-diff` stays the numeric source of truth.
- "Vergleich beenden" returns to the full-glasses view with the camera reset to default.

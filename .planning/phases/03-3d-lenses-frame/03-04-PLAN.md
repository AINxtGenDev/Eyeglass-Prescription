<objective>
## Phase Goal

**As a** non-expert holding a paper prescription (and, in the Experten-Ansicht, an optician or optometry student), **I want to** see my two lenses in 3D inside the chosen frame, turn them on my phone or desktop and, as an expert, read a thickness map, **so that** I can see how thick my glasses really are and how material or frame choice changes that, without lag.

Slice 3 makes "no lag" structural before the first picture exists. Mesh building gets its own Web Worker with latest-wins guarantees (the T-02-16 / T-02-37 patterns). It is engine/state work for the same engine-first reason as 03-02. 03-05 is its first consumer: the lazy view chunk creates the mesh worker and the client.

**Decision for lens-critic MAJOR 3 (revision 1): a dedicated mesh worker, not a mesh lane in the engine worker.** The two options were (a) one item per message in the shared worker (latest-wins per slot), or (b) a dedicated worker. Option (b) is chosen:
- It guarantees that the numbers wait for **no** mesh build. With (a) an input still waits for up to one lens build: 14–18 ms on desktop and, by the reviewer's estimate, several times that on a phone, on top of the 56,2 ms input → result measured on the Pixel 7 Pro in 02-15. That can break ENG-09 (c) (≤ 100 ms, web.dev/articles/rail).
- It is the simpler and more battle-tested change. A worker per independent workload is the standard pattern (MDN "Using Web Workers"). The compute client (ENG-09 tested, with watchdog, fallback, compare and profile lanes) stays byte-unchanged, and the new mesh client is a small, separate state machine with one lane.
- Costs, stated: one more thread, and the mesh worker bundle duplicates the engine modules it imports (design, metrics, outline, mesh/*). The SUMMARY records its size. The CSP needs no change: `script-src 'self'` already admits same-origin module workers (vite.config.js lines 16-18).
- D-26 says "the existing worker". This revision replaces that with a dedicated worker. It is allowed by 03-CONTEXT ("each decision may be revised in plan review … as long as the change keeps or improves correctness, realism or lay usability"), because it protects the numbers' latency.

Output: `transfer.js`, `mesh-protocol.js`, `mesh-client.js`, `mesh.worker.js` with Node tests, and the e2e worker URL helpers narrowed so the existing engine-worker tests keep targeting the engine worker.
</objective>

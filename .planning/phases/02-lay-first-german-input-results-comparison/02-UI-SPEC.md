# Phase 2 — UI Design Contract

> Visual and interaction contract for frontend phases. Generated by gsd-ui-researcher, verified by gsd-ui-checker.

**Mode:** `--auto`. No questions were asked. The user's standing instruction is "use best practices, it must be as easy as possible to use" (memory `best-practice-default`, 02-CONTEXT.md). Every value below is either taken from an upstream artifact (source noted) or is a best-practice default with its reason given.

**Baseline (read 2026-11-07):** `index.html`, `src/ui/style.css`, `src/i18n/de-AT.js`. The existing tokens `--fg #1a1a1a`, `--muted #4a4a4a`, `--bg #fff`, `--line #6b6b6b`, `--focus #0b57d0` and `--error #a50e0e`, the system font stack, 44 px control height, the 3 px focus outline and the "text label, never colour alone" diagnostics pattern all stay. This spec extends them; it does not replace them.

**Hard constraints carried in:** vanilla light-DOM HTML plus one CSS file (`src/ui/style.css`), no new npm dependency, CSP `style-src 'self'` (no `style="…"`, no `<style>` in SVG, no `setAttribute('style')`; classes, SVG presentation attributes, or `el.style.prop = …` only), all text through `t()` and `textContent`, de-AT only, 320 px minimum width, WCAG 2.2 AA, `references/` never copied or published (all drawings are our own SVG).

## Design System

| Property | Value |
|----------|-------|
| Tool | none. shadcn gate: not applicable (no React/Next; vanilla ES modules, project rule in CLAUDE.md "UI Approach"). No `components.json`, no Tailwind (verified with `ls`). |
| Preset | not applicable |
| Component library | none. Native elements only: `<button>`, `<input type="text">`, radio `<fieldset>`, checkbox with `role="switch"`, `<details>`, `<table>`, `<select>` (meridian picker only), inline `<svg>`. |
| Icon library | none. Six own 16×16 inline SVG icons built with `createElementNS` in `src/ui/icons.js` (presentation attributes only, `stroke="currentColor"`, `aria-hidden="true"`, `focusable="false"`): `info` (circle + "i"), `error` (triangle + "!"), `hint` (circle + "?"), `outside` (circle + slash), `check` (tick), `chevron` (not used where native `<details>` marker suffices). ## Spacing Scale

Declared values (multiples of 4), exposed as custom properties:

| Token | CSS variable | Value | Usage |
|-------|--------------|-------|-------|
| xs | `--space-1` | 4px | Icon-to-text gap, term-to-"i"-button gap, echo chip inner vertical padding |
| sm | `--space-2` | 8px | Gap between chips, label-to-input gap, echo chip horizontal padding, message top margin |
| md | `--space-4` | 16px | Card padding, page side padding on phones, gap between fields in a grid, sticky bar horizontal padding |
| lg | `--space-6` | 24px | Gap between groups inside a section, page side padding ≥ 600 px |
| xl | `--space-8` | 32px | Column gap of the two-column layout, page side padding ≥ 900 px |
| 2xl | `--space-12` | 48px | Space between top-level sections (`section + section`) |
| 3xl | `--space-16` | 64px | Space above the full-width bottom block (Experten-Analyse, disclaimer, Technische Angaben) |

Exceptions (all multiples of 4 or border/outline widths, listed so the checker does not flag them):

- **44px** minimum height and width for every interactive control: inputs, buttons, chips, radio cards, the "±" button, the switch hit area, `<summary>`, and the toggletip button hit area (existing baseline; WCAG 2.5.8 needs 24 px, 44 px is the lay/phone choice).
- **24px** visual circle of the toggletip "i" button inside its 44 px hit area.
- **56px** minimum height of the phone summary bar; **72px** `scroll-padding-bottom` on `html` (bar + 16 px) and **80px** `padding-bottom` on `body` below 900 px, so the bar never hides a focused control or the footer (WCAG 2.4.11, technique C43).
- Border widths 1 / 2 / 3 / 4 px and the 3 px focus outline with 2 px offset (existing baseline).
- `env(safe-area-inset-bottom)` added to the bar's bottom padding.
- Replace the existing `0.75rem` (12 px) disclaimer padding with 16 px. Existing `0.25rem`/`0.5rem` stay (4/8 px).

## Typography

Exactly four sizes and two weights. Sizes in `rem` (16 px root) so user zoom works; px shown for reference.

| Role | Size | Weight | Line Height | Used for |
|------|------|--------|-------------|----------|
| Label / small | 14px (0.875rem) | 400, or 600 for column headers | 1.4 | Column headers, field hints, value labels in result cards, secondary material line (Abbe, density), table cell labels in reflow mode, footer, legends of the cross-section, percentages, "Ihre Auswahl" tag, summary bar label line |
| Body | 16px (1rem) | 400 | 1.5 | All running text, inputs (16 px also prevents iOS focus zoom), echo chips (weight 600), messages, toggletip text, headline sentence of a result card, buttons (weight 600) |
| Heading | 20px (1.25rem) | 600 | 1.25 | `h1` app title, `h2` section titles. `h3` card titles use Body size at weight 600 |
| Display | 28px (1.75rem) | 600 | 1.2 | Only the four numbers in each per-eye result card (dickste Stelle, dünnste Stelle, Mitte, Gewicht). Nothing else is this size |

Weights: **400 regular** and **600 semibold** only. No italic anywhere (phase-1 note: slanted glyphs re-wrapped cells at 360 px).

Text behaviour (D-21, Research Pitfall 6):

- `html lang="de-AT"`; on `body`: `-webkit-hyphens: auto; hyphens: auto; overflow-wrap: anywhere;` (changes the existing `break-word` to `anywhere`, which counts in min-content sizing inside tables).
- Soft hyphens (`\u00AD`, U+00AD) in the dictionary at: Hornhaut·scheitel·abstand, Mindest·mitten·dicke, Mindest·rand·dicke, Pupillen·distanz, Brechungs·index, Experten·ansicht, Fassungs·maße, Hornhaut·verkrümmung, Dezen·tration.
- Numbers and units never break: format numbers with a narrow no-break space before the unit (already the `Intl` behaviour of `format.js`); wrap each formatted value in a `<span class="num">` with `white-space: nowrap`.
- Maximum text line length in the input column: 40rem.

3. The selected state of radio cards (shape, material, eye picker): 3 px accent border plus the `check` icon plus `--accent-tint` background. The check icon and the border width carry the state without colour.

Accent is **not** used for: ordinary buttons (outlined `--fg`), chips (outlined `--line`), headings, icons in messages, the "i" button at rest (outlined `--fg`; when expanded it gets a filled `--fg` circle with white "i", not accent), or any number.

**Differences ("dünner/dicker", "leichter/schwerer") get no colour at all.** They are words plus the sign of the number. No green/red pairing anywhere on the page.

## Layout and Breakpoints

Breakpoints (px, `min-width` media queries plus container queries):

| Name | Query | Effect |
|------|-------|--------|
| Phone | `< 600px` viewport | One column, page padding 16 px, summary bar on |
| Tablet | `600–899px` viewport | One column, page padding 24 px, summary bar on |
| Desktop | `≥ 900px` viewport | Two-column grid, page padding 32 px, summary bar off |
| Sticky results | `(min-width: 900px) and (min-height: 600px)` | Results column is sticky; below 600 px height it scrolls normally |
| Rx table mode | container `rx` `≥ 560px` | Real table layout; below: one card per eye (D-03, breakpoint fixed here) |
| Rx card 1-col | container `rx` `< 280px` | Fields stack 1 per row inside an eye card (only at extreme zoom) |
| Comparison table mode | container `cmp` `≥ 480px` | Material table and A/B table as real tables; below: stacked rows with visible cell labels |
| Shape cards | container `frame` `≥ 440px` | 4 shape cards in one row; below: 2×2 |
| Material cards | container `material` `≥ 360px` | 2 columns; below: 1 column |
| Frame A/B/DBL | container `frame` `≥ 400px` | 3 fields in one row; below: stacked |

Why container queries: at 900–1100 px the input column is only about 400–600 px wide, so a viewport query would put the five-column Rx table into a too-narrow column. Each block decides from its own width.

**Focal point:** the first thing the eye should land on is the four Display (28 px) numbers in the per-eye result cards (sticky results column on desktop, bottom bar on phone); everything else supports reading them.

### Desktop (≥ 900 px)

- `.layout-cols` (02-09, was `.layout`): `display: grid; grid-template-columns: minmax(0, 1fr) 400px; column-gap: 32px; max-width: 1152px; margin-inline: auto`. The existing `body { max-width: 48rem }` moves to the input column as `max-width: 40rem` for text, and `body` itself gets no max width.
- `.col-results`: `position: sticky; top: 16px; max-height: calc(100dvh - 32px); overflow-y: auto; overscroll-behavior: contain`. It gets `tabindex="0"`, `role="region"` and `aria-label` = "Ergebnis und Vergleich" so keyboard users can scroll it (axe `scrollable-region-focusable`). It contains results, material comparison and the configuration comparison, so the core-value answer is visible while the user changes inputs on the left.
- `.col-full` sits below `.layout-cols` (full width, outside the grid since 02-09: a sticky box is held inside its parent, so `.col-full` must not share the sticky column's parent), with 64 px top margin.
- `#view-slot` is the first child of `.col-results`. Phase 2 ships it as `<div id="view-slot" hidden></div>`; phase 3 fills it. The planner must not put anything else there.

### Phone and tablet (< 900 px)

- One column in DOM order. The results follow the material section.
- **Summary bar** `#summary-bar` (D-20): `position: fixed; inset-inline: 0; bottom: 0; min-height: 56px; padding: 8px 16px calc(8px + env(safe-area-inset-bottom))`, `--bar-bg`, white text. It is an `<a href="#result">` (one tap target, whole bar). Content, two lines:
  - Line 1 (14 px, `#d4d4d4`): "Dickste Stelle · Gewicht" (or "rechnet …" while pending). While the result cards show Vorher (A) the line starts with "Vorher (A): " (02-17, lens-critic M2); the toggle is never switched for the user.
  - Line 2 (16 px, 600, tabular): "R 4,1 mm · 9 g | L 3,8 mm · 8 g". Stale values get `text-decoration: underline dotted`, same as phase 1.
  - `#bar-view-slot` (`hidden`, empty) sits at the start of the bar, reserved for the phase-3 mini preview.
  - The bar is hidden (`hidden` attribute) while any part of `#result` is in the viewport (IntersectionObserver), so it never duplicates visible numbers and never covers the result cards.
  - Accessible name: "Zum Ergebnis: rechts dickste Stelle 4,1 mm, 9 g; links dickste Stelle 3,8 mm, 8 g". The bar is **not** a live region (the result cards already announce; double announcement avoided).
- Viewport meta becomes `width=device-width, initial-scale=1, interactive-widget=resizes-content` (Research D-20 change, adopted). `html { scroll-padding-bottom: 72px }` below 900 px.
- On iOS Safari the bar sits behind the keyboard while typing. This is accepted (Research Pitfall 4) because the field echo stays visible next to the field. A real-iPhone check is recorded in VERIFICATION, or marked "unverified".

### Rx table `#rx-table` (RX-01, D-01..D-05)

## Accessibility Contract (UX-04, D-39)

- WCAG 2.2 AA; axe tags `wcag2a, wcag2aa, wcag21a, wcag21aa, wcag22aa`, zero violations, in Simple, Expert, comparison-active and all-tips-open states, at 320 × 640 and 1280 × 800 (Research code example).
- Every input has a visible label in card mode and a programmatic label in every mode (`label for`). Column headers are not the only label.
- No information by colour alone: tiers have text labels and distinct icons; selection has a check icon, border width and text tag; A/B have line style and a text legend; differences are words.
- Touch targets ≥ 44 × 44 px (stricter than 2.5.8).
- Focus never hidden: `scroll-padding-bottom` for the bar; the sticky desktop column never overlaps the input column.
- 320 px: `document.documentElement.scrollWidth <= clientWidth` in all states, with hyphenation off (Research Pitfall 6). Test helpers strip U+00AD before text assertions.
- `prefers-reduced-motion` respected.
- Screen-reader manual pass (TalkBack on the Pixel; VoiceOver if an iPhone is available) for: Rx card mode, sign button, toggletip, inline confirm, comparison toggle. Result recorded in VERIFICATION.

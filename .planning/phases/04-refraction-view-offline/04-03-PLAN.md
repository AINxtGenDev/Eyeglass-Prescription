<objective>
## Phase Goal

**As a** non-expert holding a paper prescription, **I want to** look through my computed lenses in a traced "Durchblick" view and keep using the site offline after one visit, **so that** I see how my glasses change what I see and can check my numbers anywhere.

Slice 2 (engine first): the engine can produce the whole Durchblick picture mapping for a panel, including where the frame rim appears, and P0 proves with the production code that the chosen field never shows a ray that has no defined picture. This plan also turns every provisional number of the UI spec into a measured one.

**Decision recorded (orchestrator decision 6, D-02 / ROADMAP SC1):** the field angle fixed here makes a cylinder's distortion along a panel's short side small (about 1,7 px for 1 dpt). ROADMAP SC1 ("a cylinder visibly distorts along the correct axis") is therefore judged by the Mit/Ohne Glas blink, the reference ticks and the size text, which names the direction. This reinterpretation is accepted explicitly by the user on 2026-11-13; the orchestrator reported it to the user that day and recorded the report and the acceptance in session.md (round-2 NEW-10; 04-13 Task 1 checks the record, this plan does not write session.md). Its hard gate is the on-screen pixel test in 04-08 Task 1/3 (lens-critic M3: a mirrored cylinder or swapped eyes must fail on screen, not only in the warp array). 04-13 asks the user to confirm, it does not decide. The SUMMARY repeats this paragraph so lens-critic can challenge it.

Output: `outline-geom.js`, `warp.js`, their tests, the stage-size and P0 scripts, `04-P0-RESULTS.md` and the UI-SPEC update.
</objective>

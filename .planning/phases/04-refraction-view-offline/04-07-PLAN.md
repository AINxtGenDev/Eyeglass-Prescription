<threat_model>
## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| sessionStorage (same tab, shared origin) → form inputs | Data read at start could be stale, crafted or from an older build |
| service worker update → running page | A new engine must never replace the old one mid-session without the user's click (enforced by the controller here, wired in 04-14) |

## STRIDE Threat Register

| Threat ID | Category | Component | Disposition | Mitigation Plan |
|-----------|----------|-----------|-------------|-----------------|
| T-04-26 | Tampering (input injection) | takeHandover / applySnapshot | mitigate | Size cap 8 KB, JSON.parse in try, shape check, values written as field text through the normal parse/validate path (never trusted raw); invalid → update.done.lost |
| T-04-27 | Information disclosure (health-adjacent Rx at rest) | sessionStorage key | mitigate | Written only immediately before a reload, read once and deleted before use, same tab only, one key; boundary test keeps every other storage use banned |
| T-04-28 | Tampering (mid-session engine swap) | update flow | mitigate | registerType prompt, skipWaiting false, SKIP_WAITING only on the click; other tabs reload with their own handover on controllerchange (old lazy chunks cannot be fetched against a new worker) |
| T-04-29 | Denial of service (lost inputs) | failure path | mitigate | 10 s timer restores the button; nothing is written before the reload, so nothing needs cleaning; storage probe switches to the reset wording before the click |
</threat_model>

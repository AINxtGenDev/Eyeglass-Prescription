## Sources (verified 2026-11-06; Task 4 re-fetches both web.dev pages and quotes what they say now)

- **RAIL**, https://web.dev/articles/rail (orchestrator fetch, HTTP 200):
  - "Complete a transition initiated by user input within 100 ms".
  - "To ensure a visible response within 100 ms, process user input events within 50 ms".
  - "For actions that take longer than 50 ms to complete, always provide feedback".
  - "Produce each frame in an animation in 10 ms or less" (16 ms technical maximum).
  - The page itself now recommends Core Web Vitals over RAIL, so INP is the main metric and RAIL is the guideline.
- **INP**, https://web.dev/articles/inp:
  - "An INP below or at 200 milliseconds means a page has good responsiveness".
  - It measures "from the time the user begins the interaction to the moment the browser is next able to paint a frame".
  - The thresholds apply to "the 75th percentile of page loads recorded in the field". This plan applies 200 ms to every measured edit, which is stricter.
- **Event Timing**, https://developer.mozilla.org/en-US/docs/Web/API/PerformanceEventTiming:
  - Observe with `observe({ type: "event", durationThreshold: 16, buffered: true })`.
  - "the minimum possible duration threshold is 16ms".
  - The duration is rounded "to the nearest 8ms".
  - Status: "Baseline 2025 Newly available".
- **Vite workers**:
  - https://vite.dev/guide/features#web-workers: use `new Worker(new URL('./worker.js', import.meta.url), { type: 'module' })`. "The worker detection will only work if the `new URL()` constructor is used directly inside the `new Worker()` declaration". The options must be string literals.
  - https://vite.dev/config/worker-options: `worker.format` is `'es' | 'iife'` with default `'iife'`. This plan sets `'es'`.
- **CSP**:
  - MDN worker-src: if `worker-src` is absent, the user agent looks for "child-src …, then the script-src …, then finally … default-src". With the built CSP `script-src 'self'`, a same-origin worker file is allowed and a `blob:`/`data:` worker is blocked.
  - MDN Using Web Workers: workers "are, in general, not governed by the content security policy of the document … that created them", except data:/blob: workers. GitHub Pages sends no CSP header. The worker loads only bundled same-origin code and makes no requests (T-01-39).
- **aria-busy**, MDN: it tells assistive technology "it should wait until the modifications or changes are complete before exposing the content to the user". The role=status diag boxes sit inside `#result`, so announcements wait (MINOR-11 kept).
- **CDP throttling does not reach the worker.** lens-critic measured this on 2026-11-06 with `scratchpad/critic4/probe.mjs` and `probe2.mjs`. With the page throttled 1× → 4×, the same job took 45,4 → 50,2 ms in the worker and 46,5 → 193,4 ms on the main thread. Throttling the worker target via `Target.attachToTarget` returned -32000 "Operation is only supported for pages, not workers".
  - Consequence: the proxy measures only main-thread criteria (a) and (b). Worker-dependent criteria (c) and (d) are estimates on the proxy and are decided on the real phone (01-11 Task 3).
  - A host-level model such as `systemd-run --user --scope -p CPUQuota=25%` slows every thread, but it is a different model (quota, not a slowdown factor). It may be named in the SUMMARY as an option. It is not used and nothing relies on it.

> Measured and recorded:

> - **(a)** Every main-thread task an input causes, including style, layout and paint, stays under one frame (< 16,7 ms). ## Design decisions (planner; orchestrator-chosen fixes marked with their finding)

- **Protocol** (pure, `src/state/compute-protocol.js`).
  - Main → worker:
    - `{ type: 'compute', id, eyes: { OD?: { seq, spec }, OS?: { seq, spec } } }`;
    - `{ type: 'bench', id, caseId, k }`: **one run per job** (M1). `caseId` is one of `normal | frameMiss | grenzfall | rescan`. `k` is the frame-miss counter, supplied by the client so it never repeats across jobs.
  - Worker → main:
    - `{ type: 'ready' }` on start;
    - `{ type: 'result', id, eyes: { OD?: { seq, result } … }, computeMs }`;
    - `{ type: 'bench', id, caseId, ms, ok, evaluations }`;
    - `{ type: 'error', id, eyes: [...], message }`.
  - The handler never throws.
- **Scheduling** (M1).
  - At most one job is in flight. Compute wins: whenever the worker becomes idle and any eye has a wanted seq that has not been sent, the client sends a compute job. Only otherwise does it send the next bench run.
  - A compute request therefore waits for at most one in-flight job: one bench run (worst case the rescan pair, 178 ms per pair on the main thread at 4×) or one compute job.
  - The client collects bench run times per case. After BENCH_RUNS runs it calls `onBench(caseId, { median, tail, runs })`, using medianOf/tailOf with TAIL_PCT 95.
  - The worker is **not** terminated when a job is superseded: a restart reloads the module and loses JIT warm-up, and the wait is already bounded by one job. A stale result is simply dropped.
- **Latest-wins** (T-01-38). A response is applied per eye only if its seq equals that eye's latest wanted seq.
- **Error** (MINOR-1). For an `error` response, only the eyes whose in-flight seq still equals the wanted seq get `onFailed`. Superseded eyes stay pending and are re-sent.
- **Transfer.** No transferables. LensResult contains only plain objects, numbers, strings, booleans and null; it has no typed arrays (checked in evaluate.js and metrics.js). A structuredClone round-trip test proves it.
- **Per-eye memo and cache.**
  - An eye whose `JSON.stringify(spec)` equals its last wanted key is not re-sent.
  - A key equal to the last received result's key is delivered from the cache with no round trip. This also covers retyping the previous value while busy (MINOR-3).
  - `src/state/memo.js` then has no importer, so `git rm` it and its test once `grep -rn memoLast src test e2e` shows only those two files.
- **Busy, per eye** (MINOR-2).
  - `BUSY_AFTER_MS = 50`. Each eye has its own open timestamp and timer, with `delay = max(0, 50 − (now − openTs))`.
  - The client calls `onBusy(eye, true)` when the timer fires and the eye is still open. It calls `onBusy(eye, false)` when that eye's current result is delivered (including from the cache) or the eye is cancelled.
  - On the page:
    - `#result` gets `aria-busy="true"` while any eye is busy;
    - that eye's Hinweis cell shows `t('result.computing')` ('rechnet …');
    - its value cells get `data-stale="true"`, styled italic with a dotted underline; there is no opacity change, so axe contrast is unaffected;
    - `#calc-status` shows `t('result.computingNote')` while any eye is busy.
  - `renderResult` always renders a delivered result; the 01-14 identity skip `showResult` is removed (MINOR-3). The MINOR-11 signature check still keeps diag boxes quiet. renderResult restores the status cell and clears that eye's data-stale.
  - `#calc-status` sits **below** the result table and above the diag boxes, with `min-height` reserved, so showing it shifts nothing (MINOR-5). It is a plain `<p>`, not a live region.
- **Fallback and watchdog** (MINOR-4, MINOR-12).
  - The client switches to fallback in three cases:
    - the Worker constructor throws;
    - an `error` event arrives before READY;
    - no READY arrives within `WATCHDOG_MS = 10_000` of start, or an in-flight job gets no response within `WATCHDOG_MS`. A bench job is one run, so 10 s is far above the 01-14 worst run.
  - In each case the client calls `onFallback(reason)`, with reason `'start'` or `'timeout'`.
  - On fallback, the page terminates the worker, loads the handler with a **dynamic** `import('../state/compute-protocol.js')`, so the engine is not in the entry chunk twice, and calls `client.useTransport(syncSend)`.
  - `syncSend` is `(msg) => setTimeout(() => client.receive(handle(msg)), 0)`. Every job, including each single bench run, is its own macrotask and the page yields between them (M1). One heavy job can still stall the page once, for up to one rescan pair, and `tech.mode.sync` says so.
  - `#compute-mode` gets `data-mode="sync"` and the text `t('tech.mode.sync')` for reason `start`, or `t('tech.mode.syncTimeout')` for reason `timeout`.
  - If the dynamic import fails, the open eyes render as failed.
- **Timing** (M4).
  - The 01-14 after-paint method (rAF + setTimeout, Nolan Lawson 2018) is kept for both frames.
  - **Input frame:** `inputFrame` runs from the start of the frame callback that reads the inputs and sends the job to the setTimeout task after its paint. `reaction` runs from the input's timeStamp to that same point.
  - **Result frame:** `client.receive` only stores the delivery and requests one rAF, coalescing several deliveries into one frame. Rendering happens in that rAF. `resultFrame` runs from that rAF's start to the setTimeout task after its paint. `result` runs from the earliest open input's timeStamp to that same point, and is pushed only when no eye is still open.
  - `compute` is the worker's `computeMs`.
  - Rings hold the last 10 values. The readouts show the median and the longest value.
  - Event Timing is an informational cross-check. The page shows the longest duration of the last 10 `event` entries with `interactionId > 0`, feature-detected via `PerformanceObserver.supportedEntryTypes`. If the API is supported but has no entries, it shows `t('tech.eventTimingEmpty', { threshold })` (MINOR-10). If it is unsupported, it shows `t('tech.eventTimingNone')`.
- **Lint** (MINOR-8).
  - Add a `src/worker/**/*.js` block with `globals.worker` (checked: globals 17.14.0 has `worker` with `self` and `postMessage`), plus no-restricted-imports for three and `**/ui/**`.
  - Add `no-restricted-globals` to the existing `src/state/**` + `src/i18n/**` non-test block: window, document, navigator, self, localStorage, sessionStorage, requestAnimationFrame, fetch, XMLHttpRequest. `performance` stays allowed because Node has it. Task 1 confirms the existing state and i18n files still lint clean.
- **CSP stays exactly** `default-src 'self'; script-src 'self'; style-src 'self'; img-src 'self' data:; object-src 'none'; base-uri 'self'; form-action 'none'`. Task 2's e2e checks it with an exact string equality against the served HTML (MINOR-8).

## Settled signal (lens-critic MAJOR-3)

- **Where it is set.** main.js keeps `#result[data-pending]` as a space-separated token set, written whenever the set changes:
  - `input` from the moment an input or change event schedules a frame until that frame has run;
  - `OD` or `OS` while that eye is open in the client, or delivered but not yet painted.
- **When it clears.** The value is `""` when nothing is pending. It is cleared inside the result rAF, after painting.
- **Helper.** `e2e/helpers.js` exports `settled(page)`:
  1. `await expect(page.locator('#result')).toHaveAttribute('data-pending', '')`;
  2. one `page.evaluate` of rAF + setTimeout, so the frame has painted.
- **Why it is deterministic.** Playwright `fill` dispatches `input` synchronously, so `input` is in the set before `settled` runs.
- **Where it is used.** Every smoke, worker and perf test that reads a `#result-*`, `#diag-*` or `#timing-*` value after an edit calls `settled(page)` first. Task 2 lists every adapted test in the SUMMARY.

## Design decisions

### Protocol

`src/state/compute-protocol.js` is pure. Messages:

| Direction | Message |
|---|---|
| main → worker | `{ type: 'compute', id, eyes: { OD?: { seq, spec }, OS?: { seq, spec } } }` |
| main → worker | `{ type: 'bench', id, caseId, k }`: **one run per job**. `k` is the frame-miss counter, supplied by the client. |
| worker → main | `{ type: 'ready' }` |
| worker → main | `{ type: 'result', id, eyes: { OD?: { seq, result } … }, computeMs }` |
| worker → main | `{ type: 'bench', id, caseId, ms, ok, evaluations }` |
| worker → main | `{ type: 'error', id, eyes: [...], message }` |

The handler never throws.

### Scheduling

- One job is in flight at a time, and compute always comes first: when the worker becomes idle, a pending compute job is sent before the next bench run.
- So a compute request waits for at most one job. The worst case is one rescan-pair run.
- The worker is not terminated when a job is superseded. A restart would reload the module and lose the JIT warm-up, and the wait is already bounded.
- `bench(caseIds)` returns false while a bench is running (re-entry guard).
- A bench run answered with `error` ends the bench with `onBench(caseId, { error: true })` and resets `isBenchRunning()` (MINOR-3).

### Latest-wins and staleness

- Deliveries carry the per-eye seq. The client applies a response per eye only if its seq equals the wanted seq.
- The page re-checks `client.isCurrent(eye, seq)` again inside the result rAF before painting (MINOR-1). This covers an input that arrives between the delivery and the frame.

### Errors

- An `error` response fails only the eyes whose in-flight seq is still current. The other eyes stay pending.
- `workerError()` after READY clears the in-flight job and its watchdog, fails the current eyes, and dispatches pending work (MINOR-3).

### Transfer

- No transferables are used. LensResult has no typed arrays. A structuredClone round-trip test proves the results survive.

### Memo and cache

- An unchanged spec key (`JSON.stringify(spec)`) is not re-sent.
- A key equal to the last result is delivered from the cache, which covers retyping the previous value while a job is busy.
- `memo.js` and its test are deleted (`git rm`) once `grep -rn memoLast src test e2e` shows only those two files.

### Busy state (per eye)

- `BUSY_AFTER_MS = 50`, timed per eye from its earliest open input.
- When the timer fires, `onBusy(eye, true)` sets:
  - the status cell to 'rechnet …';
  - `data-stale` on the value cells;
  - `aria-busy` on #result;
  - the #calc-status text;
  - and increments the busy counter.
- `onBusy(eye, false)` clears **only** `data-stale`, aria-busy (when no eye is still busy) and #calc-status. It never writes the status cell (MINOR-2). renderResult, renderEmpty and renderFailed own the status cell, so a message such as "Bitte zuerst …" is not overwritten.
- The delivery of the result, or a cancel, clears the marks in the same frame as the new values. Delivery happens in a message task, and the rAF paints before the next frame.
- The 01-14 identity skip in showResult is removed.

### Layout (MAJOR-2)

- `td[data-stale]` gets only `text-decoration: underline dotted`, with **no italic**: italic changes glyph widths and re-wrapped the base-curve cell at 360 px.
- `#calc-status` sits below the result table with `min-height: 3lh` (fallback `4.5em`; see Sources).
- `t('result.computingNote')` is shortened to 'rechnet … Die Werte gehören noch zur vorigen Eingabe.'
- Test 5 asserts unchanged bounding boxes for `.result-table`, `#calc-status` and `#disclaimer` on both projects. The mobile project is 360 px wide.

### Fallback and watchdog

- `WATCHDOG_MS = 10_000`.
- **What triggers the fallback:**
  - the Worker constructor throws;
  - `error` arrives before READY;
  - READY is missing, or an in-flight job has no answer, after 10 s.
- **Hidden or suspended tabs (MINOR-4):**
  - The client receives an injected `isHidden()`.
  - A watchdog that fires while hidden, or fires late (elapsed > watchdogMs + 1000, which means the timers were suspended), re-arms instead of falling back.
  - The page calls `client.resume()` on `visibilitychange` to visible, which re-arms the timer.
  - The order of the visibilitychange event and the throttled timers on resume is **UNVERIFIED**. The late-fire rule covers either order, and the unit tests cover both.
- **Fallback steps:**
  - terminate the worker;
  - `import('../state/compute-protocol.js')` dynamically;
  - `client.useTransport((msg) => setTimeout(() => client.receive(handle(msg)), 0))`;
  - set `#compute-mode[data-mode="sync"]` with `tech.mode.sync` or `tech.mode.syncTimeout`.
- **Bench in sync mode (MINOR-6):** opening #tech does **not** auto-start the bench; only the button does. Labels use `{where}` = `t('tech.where.sync')` ('direkt auf der Seite') instead of 'im Hintergrund'.

### Timing (main-thread)

- The 01-14 after-paint method is kept: rAF + setTimeout (Nolan Lawson 2018).
- **Rings** (last 10 values each):
  - `inputFrame`: frame-callback start → after paint;
  - `reaction`: input timeStamp → after paint;
  - `resultFrame`: result-rAF start → after paint;
  - `result`: earliest open input → after paint, recorded only when no eye is still open;
  - `compute`: the worker's `computeMs`.
- **Event Timing:** shown with three states, `values`, `tech.eventTimingEmpty` and `tech.eventTimingNone`.
- **New readout (MINOR-8):** `#timing-busy` = `t('tech.busy', { count, longest })`.
  - `count` is the number of busy displays since load, formatted with Intl.
  - `longest` is the longest `result` value since load. It is not limited to the ring.

### Lint

- `src/worker/**` gets `globals.worker` and no-restricted-imports for three and ui.
- `src/state/**` and `src/i18n/**` (non-test) get `no-restricted-globals`: window, document, navigator, self, localStorage, sessionStorage, requestAnimationFrame, fetch, XMLHttpRequest.

### CSP

The CSP stays exactly:

`default-src 'self'; script-src 'self'; style-src 'self'; img-src 'self' data:; object-src 'none'; base-uri 'self'; form-action 'none'`

It is checked by exact equality against the served HTML.

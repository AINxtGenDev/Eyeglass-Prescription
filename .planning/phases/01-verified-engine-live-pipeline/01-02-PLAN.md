Locked decision D-01 (amended again by the user 2026-11-06, "pick thinnest that works"): errors only for mathematical impossibility. Automatic base curve = Vogel clamped to [+0.50, +10.00] (rule `vogel` / `vogel-clamped`, reason `'range'`). Fallback path, entered only when (i) the frame-size limit binds (Vogel-clamped D1 > maxD1, i.e. R1 < ρmax + `FRONT_RADIUS_MARGIN_MM`; ρmax = largest distance from the optical centre to the outline) or (ii) the lens at the Vogel-clamped D1 returns FRONT_SAG_UNDEFINED or BACK_SAG_UNDEFINED: search D1 over [+0.50, +10.00] for the computable value that gives the thinnest lens and report `BASE_CURVE_CLAMPED` with reason `'frame-optimised'` and rule `'frame-optimised'` (replaces the former reason `'frame-size'` and rule `'vogel-frame-limited'`). An error is returned only if no D1 in the range computes. Normal lenses pay nothing: one solve, as before.

Planner's choices inside D-01 (Claude's discretion, justified):
- Criterion: minimise J(D1) = max(CT, largest outline edge thickness), i.e. the thickest point of the lens. For plus-dominant lenses this is the centre thickness, for minus-dominant lenses the maximum edge thickness, for mixed lenses whichever is larger. One criterion, no case split; ties keep the first minimum found in scan order.
- Search (`optimiseBaseCurve` in `solve.js`, bounded): (1) coarse scan D1 = 0.50, 1.00, 1.50, … below the upper bound hi = maxD1, plus hi itself, solving on a decimated outline (every 4th point; a subset of the outline can only under-report violations, so a coarse point that fails is genuinely infeasible), each solve warm-started from the last feasible CT; (2) if no coarse point computes, rescan [+0.50, +10.00] in 0.10 dpt steps on the decimated outline, ignoring the margin, so that an impossibility claim covers the whole allowed range; still none → error; (3) golden-section refinement on the full outline in [best − 0.50, best + 0.50] ∩ [0.50, bound], infeasible points counting as +∞, until the bracket is ≤ 0.05 dpt; the result is the full-outline-feasible D1 with the smallest J among all full-outline evaluations (the coarse best is re-evaluated on the full outline first); if none is feasible (decimation hid a violation), repeat the coarse scan on the full outline and refine again. No snapping to 0.25 dpt steps: snapping moves the answer up to 0.125 dpt off the minimum and has no manufacturing meaning in this model; the UI shows two decimals. Bound per eye: ≤ 21 coarse + ≤ 96 rescan (failing lenses only; an infeasible solve exits at the first NaN point) + ≤ 10 refinement solves (one extra full-outline coarse pass in the rare decimation case).
- Prototype evidence (planner, 2026-11-06, node, 720-point outline, rechteckig as superellipse p = 5; orientation only, to be confirmed by the engine tests): over a 4,608-case grid (sph −12/−6/0/+3.5/+6/+12, cyl 0/−2/−6, axis 0/45/90, four shapes, A/B/DBL/PD extremes, CR-39 and 1.74) 437 lenses took the fallback path, 149 were optimised and 288 were impossible; a 0.05 dpt brute-force sweep rescued none of the 288 and beat no optimised result by more than 1e-5 mm; ≤ 29 solves per eye on optimised lenses; desktop median for both eyes 3.0–4.1 ms on fallback lenses vs 1.0 ms on the normal path (outline solve only, without the volume grid).
- Error code when no D1 computes: the code of the full-outline solve at D1 = 0.50 (the flattest allowed front; it covers any real frame, so the binding failure is the back surface), with `data.searched = true`. So the automatic base curve never reports FRONT_SAG_UNDEFINED for a real frame (that would need ρmax > K(n)/0.5 ≈ 1000 mm); FRONT_SAG_UNDEFINED stays reachable with a manual base curve.
- `FRONT_RADIUS_MARGIN_MM = 2` is kept as a numerical guard, not a physical limit: it defines the fallback trigger and the search's upper bound so that q = 1 − ρ²/R1² ≥ 1 − (ρ/(ρ + 2))² (≈ 0.075 at ρ = 52 mm) stays away from 0, where the sag slope ρ/(R1·√q) diverges and the CT fixed point becomes ill-conditioned. In the prototype the optimum never touched this bound (same result with and without it). A-priori constant; never tune it to make a test pass.
- `baseCurveAuto` takes the front conic constant `k1` now (default 0), so the phase-2 asphere cannot reintroduce FRONT_SAG through the automatic curve: q = 1 − (1 + k1)·c1²·ρ² ≥ 0 gives the cap K(n)/((ρmax + margin)·√(1 + k1)) for 1 + k1 > 0 and no cap otherwise.
- Known consequence of "search only on the fallback path" (the user's decision; recorded, not changed): where the cap binds, CT is not monotone in the sphere. Prototype, rechteckig 62×55, DBL 24, PD 25, CR-39: +3,25 → Vogel D1 9.25, CT ≈ 16.8 mm; +3,50 → frame-optimised D1 ≈ 2.28, CT ≈ 10.3 mm. The range-clamped +12 in 62×55/18/32 keeps D1 10 (CT ≈ 25.0 mm) although D1 ≈ 7 would give ≈ 23.0 mm. The SUMMARY records the engine's values for these cases.

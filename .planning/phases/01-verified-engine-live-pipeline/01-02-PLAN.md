Locked decision D-01 (final amendment by the user 2026-11-06, "always pick the thinnest"): for every lens with `baseCurve: null`, the automatic base curve is the D1 in [+0.50, +10.00] that minimises the maximum lens thickness, found by the bounded search below (rule `'thinnest'`). Vogel's rule (clamped to [+0.50, +10.00]) is still computed, shown only as a sourced reference value ("Vogel-Richtwert"), and seeds the search. Errors only if no D1 in the range computes. This replaces the earlier fallback-only design (rules `vogel` / `vogel-clamped` / `frame-optimised` and reasons `range` / `frame-size` no longer exist). REQUIREMENTS MAT-02 ("documented, sourced rule") is being re-worded by the orchestrator to "thinnest feasible, Vogel as sourced reference"; do not edit REQUIREMENTS.md.

Planner's choices inside D-01 (Claude's discretion, justified):
- Criterion: minimise J(D1) = max(CT, largest outline edge thickness), i.e. the thickest point of the lens. For plus-dominant lenses this is the centre thickness, for minus-dominant lenses the maximum edge thickness, for mixed lenses whichever is larger. Ties keep the first minimum found.
- Search (`optimiseBaseCurve` in `solve.js`, bounded, deterministic): upper bound hi = maxD1 = min(10, front cap) from `baseCurveAuto`. (0) Vogel seed: always solve the full outline at the Vogel-clamped D1 (even above hi — the margin only bounds the scan); if it computes it is a candidate, so the result is never thicker than the Vogel lens, and its J is reported as the reference thickness (null only when the Vogel lens does not compute). (1) coarse scan D1 = 0.50, 1.00, 1.50, … below hi, plus hi, on a decimated outline (every 4th point; a subset can only under-report violations, so a coarse point that fails is genuinely infeasible), each solve warm-started from the last feasible CT; (2) if no point computes, rescan [+0.50, +10.00] in 0.10 dpt steps on the decimated outline, ignoring the margin, so an impossibility claim covers the whole allowed range; still none → error; (3) golden-section refinement on the full outline in [best − 0.50, best + 0.50] ∩ [0.50, bound], infeasible points counting as +∞, until the bracket is ≤ 0.05 dpt; the result is the full-outline-feasible candidate with the smallest J (Vogel seed included); if refinement finds nothing feasible (decimation hid a violation), repeat the coarse scan on the full outline and refine again. No snapping to 0.25 dpt steps (it can move the answer up to 0.125 dpt off the minimum and has no manufacturing meaning here); the UI shows two decimals. Bound per eye: 1 seed + ≤ 21 coarse + ≤ 96 rescan (failing lenses only; an infeasible solve exits at the first NaN point) + ≤ 10 refinement solves (one extra full-outline coarse pass in the rare decimation case).
- Prototype evidence (planner, 2026-11-06, node, 720-point outline, rechteckig = superellipse p = 5; orientation only, confirmed or corrected by the engine tests): a 0.05 dpt brute-force sweep rescued none of 288 impossible specs in a 4,608-case grid and, on a random sample of 287 computable specs (all shapes, CR-39/1.74, sph −12…+12, cyl 0…−6, any axis), beat the search by at most 2e-6 mm. Normal lenses now cost ≈ 28–30 solves per eye instead of 1 (see Performance below). Example results: −2,00 rund 50/18/32 → D1 0.50, J 3.27 mm (Vogel 5.00 would give 3.41); +12,00 rund 50/18/32 → D1 ≈ 7.6, J ≈ 9.75 (Vogel-clamped 10.00: 9.86); minus lenses generally end at the +0.50 floor.
- Performance (ENG-09, the search now runs on every recompute): prototype desktop median for both eyes, outline solves only (no volume grid; the engine adds roughly 0.2–0.5 ms per lens for it): normal cases −4/−2×30 rechteckig 52×38/18/32 1.6 ms (Vogel-only was 0.6 ms), −2 rund 50/18/32 1.1 ms (0.35), +6/−2×30 52×38/18/32 2.9 ms (0.9); worst cases +6/−2×30 in 62×55/24/25 3.8 ms and +12 rund 50/18/PD 10 2.8 ms; impossible SC-4 lens 0.8 ms. With an assumed 3–6× phone factor (RESEARCH A7, unverified) the phone lands around 5–25 ms against the 16.7 ms budget; 01-11 measures it.
- Error code when no D1 computes: the code of the full-outline solve at D1 = 0.50 (the flattest allowed front; it covers any real frame, so the binding failure is the back surface), with `data.searched = true`. The automatic base curve therefore never reports FRONT_SAG_UNDEFINED for a real frame (that would need ρmax > K(n)/0.5 ≈ 1000 mm); FRONT_SAG_UNDEFINED stays reachable with a manual base curve.
- `FRONT_RADIUS_MARGIN_MM = 2` is kept as a numerical guard, not a physical limit: it bounds the search (D1 ≤ K/(ρmax + 2)) so that q = 1 − ρ²/R1² ≥ 1 − (ρ/(ρ + 2))² (≈ 0.075 at ρ = 52 mm) stays away from 0, where the sag slope ρ/(R1·√q) diverges and the CT fixed point becomes ill-conditioned. In the prototype the optimum never touched this bound. A-priori constant; never tune it to make a test pass. The impossibility rescan ignores it.
- `baseCurveAuto` takes the front conic constant `k1` (default 0), so the phase-2 asphere cannot reintroduce FRONT_SAG through the automatic curve: q = 1 − (1 + k1)·c1²·ρ² ≥ 0 gives the cap K(n)/((ρmax + margin)·√(1 + k1)) for 1 + k1 > 0 and no cap otherwise.
- Diagnostics: no warning or info diagnostic for the normal case. `BASE_CURVE_CLAMPED` is removed from the catalogue; the difference from Vogel is an info field in `intermediates` (`vogelD1` raw, `vogelClampedD1`, `vogelMaxThickness` = J at the Vogel-clamped D1, or null exactly when that lens does not compute).
- Eye symmetry: OD and OS run the search on mirrored outlines whose floating-point samples are not exact point reflections, so the chosen D1 may differ by round-off on flat optima. Every OD/OS equality test at 1e-9 therefore compares the geometry at a common D1 (OS re-evaluated with `baseCurve = OD.intermediates.D1`) and separately asserts |J(OS) − J(OD)| ≤ 0.01 mm for the automatic results.
